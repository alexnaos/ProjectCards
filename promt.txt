# ЗАДАЧА: Генератор карточек проектов для Obsidian Vault

## Контекст
Есть Obsidian Vault по пути C:\YandexDisk, разложенный по папкам проектов (архитектура/строительство).
В каждой папке лежат разнородные файлы: PDF, DOCX, XLSX, PPTX, MD, TXT, JPG/PNG.
Нужен Python-скрипт, который для каждой папки проекта создаёт/обновляет одну
заметку-карточку `<имя_папки>.md` с YAML frontmatter. Скрипт запускается вручную
или по cron. DWG/DXF обрабатывать НЕ НУЖНО — эти форматы исключены из scope.

## Стек
- Python 3.11+
- Зависимости: pymupdf (fitz), python-docx, openpyxl, python-pptx, pyyaml,
  Pillow, requests, python-dotenv, tqdm
- LLM для описания: через OpenAI-совместимый API (base_url + api_key + model
  в .env). Должна быть возможность выключить LLM и работать в fallback-режиме
  (TF-IDF по ключевым словам).
- Поиск изображений по адресу: опционально, через SerpAPI (ключ в .env).
  Если ключа нет — пропускать шаг без падения.

## Требования к полям карточки

Frontmatter (порядок фиксированный):
```yaml
---
title: "<имя папки>"
source: ""
author: ""
publish: false
published: 
created: "<ISO date — file ctime карточки, при первом создании>"
modified: "<ISO date — сейчас>"
description: "<2–4 предложения смыслового описания>"
tags: []
address: "<адрес или пусто>"
rating: null
volume_files: 0
volume_size_mb: 0.0
cover: "![[имя_файла.png]]"
schematics:
  - "![[plan_1.png]]"
  - "![[genplan.png]]"
---
```

### Логика по каждому полю

**title** — всегда равен имени родительской папки. Если карточка была
переименована вручную и не совпадает с папкой — при запуске переименовать файл
обратно в `<имя_папки>.md` (логировать это).

**created / modified** — created берётся из существующего frontmatter, если
карточка уже была; иначе — дата создания файла карточки (или сейчас). modified —
всегда текущее время при перезаписи.

**description** — пайплайн:
1. Извлечь текст из всех поддерживаемых файлов (PDF, DOCX, XLSX, PPTX, MD, TXT).
2. Обрезать каждый файл до max_chars_per_file, суммарно до max_total_chars.
3. Отправить в LLM с промптом:
   «Ты — ассистент архитектурного бюро. На основе документов проекта
   сформируй краткое техническое описание объекта (2–4 предложения):
   тип объекта, этажность, конструктив, материалы, архитектурный стиль,
   назначение. Без воды, только факты из документов. Если данных нет —
   напиши "Описание не сформировано".»
4. Fallback без LLM: TF-IDF по объединённому тексту, взять top-15 терминов,
   собрать строку «Ключевые темы: ...».
5. Если текста нет вообще — description = "" и пометить в логе.

**address** — искать в текстах файлов регулярками:
- `(?:г\.|город)\s*[А-ЯЁ][а-яё\-]+`
- `(?:ул\.|улица|пр-т|проспект|пер\.|переулок|ш\.|шоссе|д\.|дом)\s*[\wА-Яа-я0-9\-]+`
- ISO-подобные паттерны «индекс, регион, город, улица, дом».
Собрать кандидатов, выбрать самый частый/длинный. Если пусто — `address: ""`.

**rating** — НЕ вычислять автоматически. При создании — null. При обновлении —
если в frontmatter уже стоит число, сохранить.

**volume_files / volume_size_mb** — рекурсивно по папке проекта, исключая сам
файл карточки и папку `_attachments` (вложения, сгенерированные скриптом,
тоже исключить, чтобы не было рекурсии). size_mb округлять до 1 знака.

**cover** — приоритет:
1. Изображение в папке с ключевым словом из cover_keywords.
2. Первое JPG/PNG в папке.
3. Если `images.web_search.enabled` — запрос по address, скачать первый
   результат в `_attachments/<folder_slug>_cover.<ext>`.
4. Иначе пусто.
Все скачанные/сгенерированные вложения — только в `_attachments/<folder_slug>/`.

**schematics** — список:
1. Найти изображения в папке по plan_keywords.
2. Для PDF — отрендерить страницы, в имени которых (или в извлечённом
   тексте первой страницы) есть plan_keywords, в PNG (dpi=150), сохранить
   в `_attachments/<folder_slug>/plan_<n>.png`.
3. Ограничить max_plan_images.
4. Если ничего не нашли — пустой список.

**tags** — по умолчанию `[project]`. Если в тексте встречаются ключевые слова
(«жилой», «офис», «промышленный», «реконструкция», «новое строительство»),
добавить соответствующие теги. Список тегов — в коде, легко расширяемый.

## Поведение скрипта

- CLI: `python main.py [--vault PATH] [--folder SUBPATH] [--dry-run] [--force]
  [--no-llm]`
  - `--folder` — обработать только одну подпапку (для отладки).
  - `--dry-run` — вывести, что было бы записано, ничего не менять.
  - `--force` — перезаписать description даже если он уже непустой.
  - `--no-llm` — принудительно fallback.
- Логирование: `INFO` — что обработано, `WARNING` — пропущенные файлы,
  `ERROR` — исключения по конкретным файлам (не прерывать весь прогон).
- Идемпотентность: повторный запуск без изменений в файлах не должен менять
  карточки (кроме modified). Сравнивать хэши содержимого папки; хранить
  хэши в `.cache.json` в корне скрипта.
- Инкрементальность: если хэш папки не изменился и карточка существует —
  пропускать (логировать «skipped»).
- Не трогать пользовательские поля, которых нет в спецификации (сохранять
  как есть при слиянии frontmatter).
- Не перезаписывать непустой description при изменении, если `--force` не указан.

## Обработка ошибок
- Битый PDF/DOCX — WARNING, пропустить файл.
- LLM вернул ошибку — WARNING, использовать fallback для этой папки.
- Нет доступа к сети — пропустить web-поиск.
- Нет папки `_attachments` — создать.

## Что НЕ делать
- Не обрабатывать DWG/DXF/DWS — игнорировать полностью.
- Не использовать Obsidian API (работаем с файлами напрямую).
- Не добавлять плагины Obsidian как зависимость — скрипт должен работать
  без запущенного Obsidian.
- Не писать в консоль ключи из .env.

## Acceptance criteria
1. Запуск `python main.py --dry-run --folder <тестовая_папка>` выводит
   предполагаемый YAML без записи.
2. Запуск без dry-run создаёт `<имя_папки>.md` в папке проекта с корректным
   frontmatter и всеми полями.
3. Повторный запуск не меняет description и не дублирует вложения.
4. Переименование папки + запуск → карточка переименована, title обновлён.
5. PDF с планом → PNG появляется в `_attachments/<slug>/` и попадает
   в `schematics`.
6. В `_attachments` ничего не «мусорится» при повторных прогонах.
7. README описывает установку, конфиг, запуск, cron.
